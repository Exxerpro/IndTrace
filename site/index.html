Every part, every station, on the record.

IndTrace records what happens to each serialized part as it moves through a PLC-connected production line, and checks every arrival against the part's routing. Your machines and operators stay in charge. IndTrace keeps the history and flags what should not have happened.

It tracks. It does not control.

Most problems in traceability come from systems that try to run the line. IndTrace does not. The equipment decides where a part goes; IndTrace decides whether that move was legal, and keeps the evidence.

The line decides

  • The PLC and the operator move the part and run the process.
  • Each station judges its own cycle: pass or fail.
  • When a part reaches a station, the PLC reports it in.

IndTrace records and validates

  • Stores the barcode, station, cycle result, process values and time.
  • Checks the arrival against the product's routing: is this station a legal next step?
  • Answers the PLC with an acknowledgement and a validation result.

It never sends a "go to machine X" command.

How it is built

A hexagonal .NET 10 solution. Vendor drivers sit behind a small device contract, so the core never depends on a PLC brand.

Community edition

Ships an in-memory simulated PLC controller, so the whole stack runs without hardware.

Drivers plug in

Siemens S7 and Cognex DataMan drivers implement the same contract in the commercial edition.

Two dispatchers

PLC traffic and UI requests go through separate CQRS dispatchers, each with its own bounded context.

Built for a plant floor

A wrong record can stop a line or ship a bad part, so the codebase holds a strict gate on every change.

Get started

  1. Install the .NET 10 SDK, then clone and build. The build treats warnings as errors.

    git clone https://github.com/Exxerpro/IndTrace.git
cd IndTrace
dotnet build Src/IndTrace.sln

  2. Run a test suite. Suites run on Microsoft Testing Platform, so use dotnet run.

    dotnet run --project Src/Tests/Core/Aggregation.BoundedTests/Application.AgregationTests.csproj

  3. Point the hosts at a SQL Server and start them. A step-by-step guide for an empty database and a simulated line is in progress in issue #1.
